# 案例：黄海项目的生成约束

仅为案例。下面的约束只属于黄海项目，其他项目从自己的资料库读取这些开关，不继承这里的任何选择。

## 原项目的约束

用户为黄海项目明确规定：

- 画面上不出现字幕、对白或翻译字幕、片名或人物名条、logo、水印。
- 声音上不要背景音乐、音效、动作声、环境声或底噪，只保留原稿里的角色对白和自语，没有对白的段落保持静音。
- 这些约束要按原意完整写进每一次实际发送的视频提示词。

原项目里还有一条与服装有关的教训：身份参考图上人物穿的是西装，而剧情场次里应当是战时便服。只在文字里说明“穿便服”并不能消除参考图带来的冲突，需要换用同时呈现原脸和本场服装的参考图。

## 从这个案例里留下来的通用做法

这些已经写进新版套组的通用规则，不依赖黄海项目：

1. 项目的负面约束必须进入每一次实际发送的完整请求，不能只存在资料库、聊天或没发出去的表格里。
2. 提交前看参考图的实际内容，不只看文件名。图上的服装、人物、道具与本场不符时，换图，不指望文字压过图片。
3. 每张参考图登记它具体控制什么。场景图和风格图里出现的人，不能覆盖角色的身份参考。
4. 提示词写了不等于结果做到了。成片要逐段检查约束是否真的被遵守，违反的标需返修。
5. 无背景音乐不等于静音，这两个开关要分开登记。
