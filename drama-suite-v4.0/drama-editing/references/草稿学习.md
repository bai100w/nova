# 草稿学习：从已有剪辑工程学习

下面以剪映草稿为例。其他剪辑软件的工程文件按同样的证据原则处理，把文中的工具换成该软件可用的读取方式。

目标是把真实发生的剪辑操作写成可迁移方法。先确定证据，再命名技巧。

## 定位、版本和只读检查

1. 从用户给出的草稿名、封面、时长定位。先查草稿索引和软件的自定义保存路径；默认目录不是唯一位置。名称、路径、时间线 ID、修改时间、时长和源文件散列写入记录。
2. 只读保存必要的工程/附件快照到项目规定目录；不覆盖原工程、不调用 `overwrite=True` 自修复，不清锁文件。打开软件可能改变自动保存元数据，不能因此声称原文件字节不变。
3. 环境里有 `jianying-editor` 等剪辑工具 skill 时，先用它提供的工程读取脚本（例如 `draft_inspector.py`）。主文件不是明文 JSON 时记录实际错误，改用剪映界面及可读附件。`duration=0, tracks=[]` 的 template.tmp 可能只是空模板，不能顶替当前草稿；`.bak` 也不自动代表明文或最新状态。
4. `key_value.json`、操作日志、素材库和算法缓存只提供线索。有素材 ID、segmentId 或 human/background 文件不等于最终仍在轨；浏览过的素材不等于采用。检查最终轨道、启用状态、片段范围和效果面板。
5. 通过已知素材名查找原片及既有导出，只读取与指定参考有关的媒体。时长相同、封面相同不证明版本一致；将导出和当前画面、字幕、关键切点交叉核对。有差异则分开记录为“当前草稿”“历史缓存”“既有导出候选”。

## 四种证据分开写

| 类别 | 能支持什么 | 不能支持什么 |
|---|---|---|
| 草稿参数 / 当前 UI | 轨道布局、可见片段、面板读到的参数 | 实际听感、被遮挡的轨道、未展开的设置 |
| 原片与导出观察 | 可见字幕、画面次序、已检查的收尾效果 | 未检查范围、未听过的声音 |
| 计算测量 | 时长、帧率、响度、近似画面对齐 | 剧情效果好坏、主观声音清晰度 |
| 分析推断 | 操作可能服务的叙事任务 | 实测参数、用户确认偏好 |

抽帧注明采样密度；1 fps 无法排除短闪和抖动，4 fps 仍非连续播放。fps 滤镜可能重采样到附近帧，拼图编号不是精确源时码；比较字幕或切点的版本差异时，用源帧时间戳/原始帧号再次核对。疑似特效处加密到逐帧或回放。没有听到完整混音，验收写“声音结构已查，听感未核验”。“闪光”可能是音效名称，不应直接写成画面白闪。

## 原片—草稿—导出对照

对每一段记录：源入/出点、时间线入/出点、变速/定格、缩放/位置关键帧、效果区间、音量/淡化、字幕和声音触发事件。时间单位先核实；恒速映射只在确认速度时使用，变速曲线另记。用相邻画面和波形复核，不能把媒体清单数量当镜头数量。

优先回答：

- 切镜/推拉/景深变化是否原片已有？后期到底新增了什么？
- 同名上下音轨是重复原声、分离的人声/背景，还是另一种处理？通过面板及分轨试听确认，避免重叠放大。
- 字幕是否后加，是否跨镜头、误译或漏掉句子？AI 识别操作次数不能当字幕条数。
- 音效是否落在行动、意识变化、风险出现或揭示上？音频断点和画面断点相同，并不构成 J/L-cut。
- 结尾是定格、慢放、循环还是单帧图？渐黑、字幕、声音尾巴、署名的先后关系如何？

## 提炼与验收

深入学习至少分别检查音乐选段/情绪、BGM进退、音效、画面冲击、字幕和花字。缺一项要标“样片未用”“工具无法核验”或“尚未检查”，不能以素材清单替代。关键节点连看前奏、命中、反应与尾巴，记录几层的同拍/错拍关系。需要时用 [音画节拍](音画节拍设计.md) 提炼。

音乐音源匹配可用真实缓存与导出的多窗口波形相关交叉验证；单个高分不充分，近静音和重复波形可能误匹配。记录源起点映射、有效范围、置信依据；源0秒不等于可听瞬态，相关系数不等于概率或听感评分。无法输入音频时把乐句、音色、遮词和主观节奏列为未听审。

每条规律写“触发条件 → 操作 → 预期作用 → 不适用情况 → 来源时码/证据 → 未核验项”。样片数值只作为案例，不升格为默认预设。高峰值、字幕错译等缺陷要单列，不作为学习成果复制。

用户明确要求包装为 skill 即可更新通用方法；“学习一下”不自动授权覆盖项目已确认风格。既有规则原位保留可用部分，改动前按项目目录备份；规则文件保持单一当前入口。完成后检查 frontmatter、引用、实际文件及一个真实迁移场景；结构校验通过不等于样片视听全部通过。
