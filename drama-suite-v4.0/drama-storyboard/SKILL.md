# 分镜

分镜是导演在纸上把片子拍一遍。剧本说发生了什么，分镜决定观众在每一秒看到什么、从什么角度看、看多久。

旧版分镜的参数很全，但没有讲为什么。模型知道要填焦距，不知道为什么这一镜该用长焦。这个模块补上镜头语法：每个镜头先有叙事目的，再有参数。

## 开工

1. 读 [共用规则](../drama-control/references/共用规则.md)。
2. 确认资产关卡设计级已通过。设计级通过后就可以做分镜和预演，依据资产的设定卡，标为“待资产复核”。资产文件到齐后，对照实际资产复核受影响的镜头（布局、比例、道具外观），这是资产关卡文件级的条件之一。
3. 从项目索引读：定稿剧本、逐段拆解和台词，可制作性审查的标注，导演阐述与情绪曲线，视觉圣经与画面预设表，表演基调，资产总表与设定卡（文件级通过后读冻结资产与白名单），尺寸与连续性，生视频模型的适配卡，形态和时长档案，项目资料库里的 `patterns/visual.md`（有的话）。
4. 按形态档案选画面合同：
   - 真人短剧、3DCG 动画：[物理摄影版](references/画面合同-物理摄影版.md)
   - 2D 动画、漫剧：[画面设计版](references/画面合同-画面设计版.md)

## 工作顺序

一场一场做，每场按这个顺序：

1. **读懂这场戏。** 剧本的场景五问：谁想要什么，什么挡着，转折在哪，结束时什么变了。再看情绪曲线上这场在什么位置。
2. **定调度。** 在布局图上安排人物的位置和移动路线，确定轴线。见 [场面构建与连贯](references/场面构建与连贯.md)。
3. **定覆盖。** 这场戏需要哪些镜头才够剪：建立、动作、对白、反应、细节。
4. **逐镜设计。** 每一镜先写叙事目的，再按 [镜头语法](references/镜头语法.md) 选景别、角度、焦段或构图、运动，按 [表演指导](references/表演指导.md) 写表演，按画面合同填画面卡。
5. **算时长。** 按台词计时、动作、反应、停顿估每镜的时长。汇总一律用脚本算，不手算：导出预演清单，运行 `build_animatic.py --check-only`。没有 Python 的环境，在交付里注明“手算，未经脚本核对”。
6. **查连续性。** 每镜结束时人物、道具、视线、光线的状态，作为下一镜的起点。

一集做完后：

7. **纸面预演。** 导出预演清单，算时间线，做结构检查和盲读测试，写一页预演摘要。见 [纸面预演](references/纸面预演.md)。档位要求时，再请剪辑模块生成文字卡预演片。
8. **评审与修改。** 按 [评分表与反模式](references/评分表与反模式.md) 评分，和预演发现的问题一起改。档位要求时做独立评审，盲读测试的独立会话可以同时完成评审。
9. **分生成包**，交总控过预演关卡。见 [分包与预演包](references/分包与预演包.md)。

## 五条原则

1. **每个镜头都有任务。** 交代空间，推进动作，传递信息，让观众看到某人的反应，强调某个细节。说不出任务的镜头删掉。
2. **观众该看哪里，由你决定。** 一个镜头只有一个视觉重点。景别、焦点、构图、光线、运动都为把观众的眼睛带到那里服务。
3. **镜头跟着情绪走。** 情绪曲线上越紧张的地方，镜头的选择越要有变化：更近、更碎，或者反过来，一个不动的长镜头。平的地方就是镜头选择一直不变的地方。
4. **场级预设打底，逐镜只写变化。** 画面预设表规定了这个场景的默认光线、色彩和镜头倾向。逐镜不重复抄写，只写这一镜与预设不同的地方。这样一致性有保证，变化也一眼可见。
5. **设计给人看，翻译给模型做。** 分镜是设计文档，不为某个模型而写。提交前由生成模块按适配卡翻译成请求。但设计时要知道模型的已知弱点，提前绕开。

## 不能做的事

- 改动确认过的台词，或为了塞进时长而删减、加速。台词有问题回剧本模块。
- 在资产关卡文件级通过之前锁定分镜和生成包。
- 用“电影感”“自然”“缓慢”代替具体的设计。
- 引用白名单以外的资产。

## 交付

- 分镜表：用 [分镜表模板](templates/分镜表模板.md)，场头写预设引用和调度，每镜一行，十列。
- 逐镜画面卡：大部分镜头靠场级预设加分镜表就够了，画面卡只给需要多写的镜头做。小样档只做高风险镜头；标准档做高风险镜头和关键镜头（开场钩子、最高点、集尾钩子）；精品档每镜一张。用对应形态的画面卡模板。
- 预演清单与预演摘要：见 [纸面预演](references/纸面预演.md)。
- 连续性状态表、生成包：见 [分包与预演包](references/分包与预演包.md)。

分镜表只记录设计值。接口实际支持的设置和生成后观察到的结果，由生成模块在请求登记里分开记录。
