# 剧本

剧本是整条流程里修改成本最低、对成片影响最大的环节。一场没有转折的戏，后面的分镜、生成、剪辑做得再精致也救不回来。所以这个模块的要求是：问题在纸面上解决，不留给下游。

## 开工

1. 读 [共用规则](../drama-control/references/共用规则.md)。
2. 从项目索引读：形态、时长、题材三份档案，世界观与剧情机制，剧情与集数，人物与关系，当前源稿，以及项目资料库里的 `patterns/script.md`（有的话）。
3. 判断任务类型：

| 任务 | 做法 |
|---|---|
| 从零开始写 | 走开发阶梯，一级过了再写下一级 |
| 修改已有剧本 | 只改用户指出的范围，交付时标明改了哪里、为什么 |
| 已有成稿要进入制作 | 先做剧本体检，再做逐段拆解和台词表 |
| 翻译或本地化 | 按台词表逐句对应，见拆解与台词表规范 |

用户锁定的情绪、叙事顺序、结尾和已确认的台词，不擅自改。体检发现问题时列出问题和修改建议，由用户决定改不改。

## 五条原则

1. **先兑现观众承诺。** 题材档案第 1 节写了观众来看什么情绪。每一场戏都问一句：它在兑现这个承诺，还是在为兑现做准备？两者都不是的戏，删掉或重写。
2. **戏是变化。** 一场戏结束时，人物的处境、关系或所知的信息必须和开始时不同。没有变化的段落只是在交代信息，观众会划走。
3. **演得出来才算写了。** 写在纸上的情绪必须有看得见、听得见的载体：一个动作、一次停顿、一件被捏紧的东西。“她很难过”拍不出来，“她把写好的消息一个字一个字删掉”可以。
4. **篇幅是硬约束。** 每一稿都做朗读计时。超出时长档就回来改剧本，取舍哪些内容留下。不把超时的稿子交给分镜去删台词或加快语速。
5. **为能做出来而写。** AI 生成有稳定的弱项。同样的戏剧效果常常有更好做的写法，在剧本阶段就选它。

## 开发阶梯

| 级别 | 交付 | 回答的问题 |
|---|---|---|
| 1 一句话梗概 | 一两句话 | 谁，想要什么，被什么挡住，赌上了什么 |
| 2 人物与关系 | 人物小传、关系图 | 这些人为什么会撞在一起 |
| 3 分集大纲 | 每集一段 | 每集的核心事件和集尾钩子是什么 |
| 4 节拍表 | 本集的节拍列表 | 每一次变化发生在哪里、占多长 |
| 5 场景大纲 | 每场的目标、阻力、转折 | 每场戏靠什么成立 |
| 6 对白稿 | 完整剧本 | 人物怎么说、怎么做 |
| 7 定稿 | 评审过线、计时达标、可制作性审查完成的剧本 | 可以交给下游了吗 |

每级的写法、过关检查和各档位的要求见 [开发阶梯](references/开发阶梯.md)。前五级一共只有几百字，却决定了后面的全部工作量，所以先把它们做对，再写对白。

## 交付前

1. 按 [可制作性审查](references/可制作性审查.md) 过一遍，输出标注表。
2. 做朗读计时，确认在时长档范围内。
3. 按 [评分表与反模式](references/评分表与反模式.md) 评分并附证据，对照反模式清单。档位要求独立评审的，按 [质量评审规范](../drama-control/references/质量评审规范.md) 执行。
4. 剧情或人物设定有变化的，先写回资料库对应槽位并记更新日志，再出新版本。

## 交给下游

- 短片和小样档的单集项目用剧本单文件交付，见 [开发阶梯](references/开发阶梯.md) 的“剧本单文件”一节，段落编号即拆解，台词由正文抽取。其他项目定稿后做逐段拆解和台词表，规则见 [拆解与台词表](references/拆解与台词表.md)。拆解表交给资产模块，用来判断这一集需要哪些角色、场景、道具和声音。
- 确认过的台词在分镜和生成阶段不能改写、缩写或重新翻译。台词有问题，回到这里改，出新版本。
- 还没确认的稿子可以交出去，但要明确标成草案。

## 事实核查

历史、科学等题材，把剧本里的说法和已核实的事实分开记录。资料上写着“真实原话”不等于已经核实。核查时找可靠的原始或权威来源，记下出处和戏剧化的边界。没核实的内容列成问题，不悄悄改进定稿。
