# 共用规则

所有模块开工前读一次。这些规则只写在这里，各模块不再重复。

## 1. 项目入口

- 从用户指定的目录或当前目录向上找 `剧集数据库/项目索引.md`，以最近的一个为唯一入口。旧项目的文件夹叫 `漫剧数据库`，同样识别。
- 先读项目索引、项目设定、制作状态，再只读本次任务相关的资料。
- 资料库是项目的唯一事实来源。索引里没登记的信息标“待定”，不从聊天里提到的其他作品、相邻项目或 skill 里的例子去猜。
- 不同项目之间不共享角色、声音、画风参数、台词语言、平台资产编号。
- 路径一律以项目根目录为基准写相对路径。

## 2. 取值优先级

同一件事有多个说法时，按下面的顺序取值：

1. 用户最新的明确决定
2. 项目配置（资料库里登记的值）
3. 形态档案的技术约束
4. 时长档案的篇幅约束
5. 题材档案的审美倾向
6. skill 里的通用默认做法

形态和时长是硬约束，题材是倾向。档案之间冲突时按这个顺序取舍，并把结果写进项目配置，下次不必重新判断。

skill 和档案里出现的例子只是例子，不是默认值。别的作品的画幅、字幕开关、音乐选择、焦段、角色，都不能带进当前项目。

## 3. 版本

- 交付物每次修改新增 `vN` 版本，旧版保留，项目索引指向当前版。
- 项目设定和索引可以原位修改，但要在更新日志里写清：旧值、新值、原因、日期、受影响的交付物。
- 只改用户要求的范围，不顺手改无关内容。
- 文件名里的“终版”“定稿”“V2”不代表已获批准。批准状态以制作状态里的登记为准。

## 4. 授权

- 已经给过的确认不重复索要。
- 可逆的整理、版本更新、已确认步骤的执行，直接做。
- 付费生成前核对四件事：授权范围、所用模型、预算和重试上限、接口是否真实可用。企划阶段的预算估算和平均镜数不是授权。
- 对外发布、给第三方发消息、购买素材，只按用户的明确授权执行。
- 缺一个决定时，只阻断依赖它的步骤，继续做其他工作，把确实缺的决定集中起来一次问清。
- 密钥只从已配置的凭据读取，不写进提示词、资料库、日志或 skill。

## 5. 如实

这一条是整套流程的地基。记录一旦失真，后面每个环节都会建在错误的前提上。

- 生成成功不等于质量通过，文件存在不等于已验收，文档齐全不等于成片通过。
- 没看过的画面、没听过的声音，标“未核验”，不写“通过”。只看过抽帧，就不能说分析了运镜、节奏或声音。
- 设计值、接口实际支持的设置、生成后观察到的结果，三者分开记录。写进提示词的数字不代表模型执行了它。
- 请求中断且没有输出，记“中断”。恢复时先查原任务和已有文件，不重复提交，不重复付费。
- 失败先诊断原因再重试，不拿同一份请求碰运气。

## 6. 状态用词

交付物状态统一用：未开始、草案、待确认、就绪、执行中、待审、通过、需返修、阻断、停用。

关卡结果统一用：未开始、进行中、阻断、通过、需复核。

“就绪”指可以提交，不是已经提交。生成成功后先记“待审”。不用完成百分比代替缺口明细。

## 7. 交付的完整含义

一份交付算完成，要同时满足三点：

1. 按该模块的方法做了，而不只是把模板填满。
2. 按该模块的评分表自评过，每个分数附了具体证据。
3. 档位要求独立评审的，评审记录已经存在。

细则见 [质量评审规范](质量评审规范.md)。

## 8. 不拖沓

整套流程的目标之一是快。规则保证质量，不是为了制造工作量。

- **只在确认点停。** 确认点见总控的推进方式。其他环节做完直接往下走，在下一个确认点一起汇报做了什么、发现了什么。
- **问题一次问清。** 需要用户决定的事攒在一起，在确认点一次问，每个问题附上你的建议。不为一件小事单独打断。
- **能并行就并行。** 没有依赖关系的工作同时做：例如角色图和声线试音，本集的生成和下一集的剧本，成片剪辑和宣发文案的初稿。
- **按档位做，不多做。** 档位不要求的文档不写。模板里整节不适用的，写一句“不适用”和原因，不逐格填写。
- **返修只改受影响的部分。** 不因为一处问题重做整份交付。
- **少花 token 也算快。** 能用脚本算的（时长、累计时间、文件核对）用脚本，不让模型逐行数。
- **不为求稳而停。** 拿不准但可以撤回的决定，按最合理的做法先做，在汇报里说明。只有花钱、发布、不可逆的事才必须等确认。

## 9. 运行环境

- 不假设有子代理、联网、定时任务或某个特定工具。有就用；没有就走手动路径，并告诉用户哪一步需要他来做。
- 需要外部工具的步骤（生成模型、剪辑软件）都有手动替代做法，见各模块说明。
- 业务脚本和产出放在项目目录里，不写进 skill 目录。
