# 模型适配规范

套组里不写任何具体模型的参数。模型由用户在立项时选定，每个模型用一张适配卡描述，卡片放在项目资料库的 `models/` 下。这样换模型只需要换卡片，不需要改 skill。

## 为什么不写死，也不随时换

- 不写死：生成模型更新很快，写进 skill 的参数很快会过期，用户能用到的模型也各不相同。
- 不随时换：分镜怎么分包取决于生视频模型的单次时长和参考图上限；同一集里换模型，人物和画风容易漂移。所以选型有固定的时点，选定后在项目内锁定。

## 选型时点

| 时点 | 必须定下的 |
|---|---|
| 立项定档 | 生图、生视频、配音三类各用哪个模型，自动还是手动 |
| 风格测试前 | 生图模型的适配卡填好并核验 |
| 正式分镜前 | 生视频模型的适配卡填好并核验，之后锁定 |
| 每次提交前 | 卡片上的上限与平台当前实际情况一致 |

音乐、音效、口型同步等其他模型，用到时再各填一张卡。

## 适配卡

用 [模型适配卡模板](../templates/模型适配卡模板.md) 填写。卡片回答七个问题：

1. 这是什么模型，做什么用，哪天核验的。
2. 能力上限是多少：单次时长、分辨率、画幅、帧率、参考图数量。
3. 能怎么控制它：首帧、首尾帧、角色参考、风格参考、镜头运动指令。
4. 声音方面能做什么：是否原生出声、是否支持口型、音频输入的限制。
5. 提示词该怎么写：语言、结构、长度、哪类词有效、负面约束怎么表达。
6. 它做不好什么：这些内容在分镜阶段就要避开或拆开。
7. 怎么调用，怎么计费。

**填卡规则：**

- 每一项的来源写清楚：官方文档、平台界面实测、或本项目的测试结果。记不清或查不到的填“未核验”，不凭印象填数字。
- 别的项目的卡片可以拿来当起点，但要重新核验日期和上限后才能用。
- “已知弱点”随项目推进持续补充。每次审片发现的稳定问题，都记回卡片。
- 核验日期超过项目约定的有效期（没有约定时按 30 天）或平台有更新时，重新核验。

## 锁定与更换

- 生视频模型在正式分镜前锁定，同一集内不换。
- 确实要换时（模型下线、效果达不到）：先更新适配卡，把分包和全部生成请求标为需复核，已生成的镜头重新检查与新镜头的一致性，再继续。
- 更换写入更新日志。

## 按镜头类型分配模型（进阶）

一个项目可以让不同模型负责不同类型的镜头，例如对白镜头用口型更好的模型，空镜和大场面用画面更好的模型。条件：

- 每个模型各有一张适配卡，卡片上写明它负责的镜头类型。
- 分镜的每个生成包标明使用哪张卡。
- 风格测试阶段先验证两个模型的画面能接在一起。

## 提示词翻译

分镜是给人和所有模型看的设计文档，不为某一个模型而写。提交前由 drama-production 按适配卡的“提示词写法”，把分镜卡转成该模型的请求。

翻译时不丢约束：站位、动作、表演、镜头、光线、完整口播、项目的负面约束，都要落进实际发送的文本。模型不支持的字段（例如精确的光圈值）改用它能理解的可见效果来表达，并在请求记录里注明“仅视觉约束”。

## 自动与手动双模式

| 模式 | 条件 | 做法 |
|---|---|---|
| 自动 | 运行环境里已经接好该模型的接口或工具，凭据已配置 | 直接提交、查询、下载，登记任务编号和费用 |
| 手动 | 没有可用接口 | 输出请求包，由用户在平台上操作，结果放回指定目录后继续 |

开始前先确认环境里真实可用的工具，不假设接口存在。两种模式的审片、登记、重试规则完全相同。

**请求包**是一份用户可以直接照做的文件，每个生成包一份，包含：

- 包编号和所含子镜
- 用哪个模型、在哪个平台、选哪些参数（画幅、分辨率、时长等）
- 按适配卡写法生成的完整提示词，可以直接复制
- 要上传的每个参考文件：包内路径、上传到哪个位置、起什么作用
- 这次生成应该得到什么，用户可以先自己看一眼的三五个要点
- 结果文件怎么命名、放回哪个目录

用户放回结果后，按正常流程审片。用户在平台上自行调整了提示词或参数的，请他告知，并记入请求登记。

## 预算与重试

立项时与用户确定：每镜的重试上限、本集的预算上限。达到上限仍未通过时停下来，说明诊断出的原因和可选方案（改分镜、拆镜、换参考、换模型），由用户决定，不继续消耗。
