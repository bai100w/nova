# 交付与状态规范

## 目录

资料放 `剧集数据库/`，原始资产放 `资产/`，各集的制作文件放 `制作/`，按需建立：

```
制作/EP01/
├── 01_剧本/
├── 02_分镜/
├── 03_预演/
├── 04_制作包/<包编号>_vN/
├── 05_生成/
├── 06_审片/
├── 07_后期/
└── 08_宣发/
```

项目已有自己的目录和编号时，沿用已有的，不为了对齐本规范而改名。

## 编号

| 对象 | 格式 | 例 |
|---|---|---|
| 源稿段落 | 集-场-段 | EP01-S01-P001 |
| 剪辑镜头 | 集-场-镜 | EP01-S01-C03 |
| 生成包 | 集-场-包 | EP01-S01-G01 |
| 包内子镜 | 集-场-包-序号 | EP01-S01-G01-02 |
| 资产 | 类别-名称-序号 | CHAR-女主-01、SCENE-天台-01 |
| 参考卡 | REF-日期-序号 | REF-20261113-01 |

剪辑镜头和生成包分开编号：一个包可以含多个子镜，一场戏可以跨多个包。编号一经使用保持稳定，版本号另列，不写进编号。

## 每份交付登记的字段

集、阶段、源版本、输出版本、项目内相对路径、状态、确认来源、验收证据、评审记录位置、阻断项、下一步、时间。

状态用词见 [共用规则](共用规则.md) 第 6 条。

## 台词表

每行保留：段落编号、说话人、类型（对白、旁白、内心独白、画外音、环境喊话）、原文、表演文本、确认状态。需要本地化时，译文另列一栏，原文不动。

冒号、引号里的字，屏幕上的字，道具上的字，不能自动当成口播。

## 资产登记

每项记录：编号、相对路径、SHA256、类别、对应角色或场景、版本、前一版、控制维度、适用场次、状态、确认依据。图片记实际像素，音频记精确时长。

文件存在只代表盘点到了，不代表验收过。提示词里写了 4K 不代表输出是 4K，以实测为准。

平台托管的资产另记：本地对应文件、平台上的组和名称及编号、用途、当前状态。同名或显示有效不等于就是这一份，要核对到具体文件。

## 生成请求登记

每次请求记录：剧本与分镜版本、源段落编号、包和子镜编号、模型及参数的核验日期、发送的完整请求文本、实际附带的每个附件及其用途、完整口播、任务编号、费用（未知就记未知）、输出位置、重试次数及原因。

手动模式下同样登记，任务编号一栏记“手动”和操作时间。

## 制作包

正式生成前，为本集建一个独立的制作包。它存在的意义是让生成环节只从一处取材，避免临时从别处借用未确认的文件。

**包内实际包含：**

- 确认的源稿和逐段映射
- 确认的台词表
- 锁定版本的完整分镜
- 资产白名单，以及白名单上每个文件的副本
- 声音配置、所选模型的适配卡
- 读取说明：读取顺序、身份与妆造的控制规则、声音格式和累计时长限制、分辨率、重试与续接策略、已排除的旧版本

**规则：**

- 制作包登记为正式入口后，包内白名单是本集生成引用的唯一来源。缺东西先补包，不从全局资产库、聊天附件、候选图或旧版本里临时借。
- 包外的文件可以用来查漏，不能直接作为提交的附件。
- 包内引用用包内相对路径。复制后逐个核对文件可读、引用有效。
- 核心设计还没确认时只叫“候选包”，不提前命名为最终包。
- 总控分别记录五件事的状态：源稿与台词确认、分镜评审、素材就绪、请求适配、成片验收。文档装订齐了不等于这五件事都过了。

## 断点续做

- 中断前记下：最近完成的步骤、外部任务编号、已产生的文件、下一步。
- 恢复时先查现有文件和外部任务的实际状态，再决定从哪里接。不凭记忆推定上一步成功了，也不重复提交已经在跑或已经完成的付费任务。
- 续接画面时，只用已经验收通过的片段做续接源。待审的、被否定的、有连续性错误的片段不能用。
- 变更只返修受影响的范围，并列出受影响的编号。

## 同步

只对用户指定并授权的仓库做同步。同步前检查本地改动和远端状态，限定本次的文件范围。密钥不入库。大体积媒体按仓库能力用 LFS 或单独的媒体存储，资料库里记相对路径、校验值和存放位置。没有绑定仓库时如实说只存在本地，不说已经云同步。
