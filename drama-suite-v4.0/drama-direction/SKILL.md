# 导演与视觉开发

这个模块回答一个问题：这部片子应该是什么感觉，以及用什么手段做出这种感觉。

没有这一步，资产、分镜、剪辑各自凭默认值工作，每个环节单看都合格，合在一起却没有性格。成片显得廉价，多数时候不是因为某个镜头做坏了，而是因为没有人做过统一的选择。

## 开工

1. 读 [共用规则](../drama-control/references/共用规则.md)。
2. 从项目索引读：形态、时长、题材三份档案，世界观，剧本开发成果（梗概、人物、大纲，有节拍表更好），用户给的参考和学习模块的参考卡，项目资料库里的 `patterns/visual.md`（有的话）。
3. 确认生图模型的适配卡已填好。风格测试要用它。

## 交付

| 交付 | 内容 | 写法 |
|---|---|---|
| 导演阐述 | 立意、基调、每个段落希望观众有的感受、三到五条视听策略 | [导演阐述](references/导演阐述.md) |
| 情绪曲线 | 全集的能量起伏，标出主峰和气口 | 同上 |
| 视觉圣经 | 色彩脚本、影调与光线、镜头或画面规则、质感、视觉母题、参考板 | [视觉圣经](references/视觉圣经.md) |
| 画面预设表 | 每个场景一套预设，分镜逐镜引用 | 同上 |
| 表演基调 | 表演的写实程度、幅度、节奏，每个主要人物的表演关键词 | [表演与声音概念](references/表演与声音概念.md) |
| 声音概念 | 音乐、环境声、标志性声音、静默的用法 | 同上 |
| 风格测试 | 两到三张代表性风格帧，验证阐述能做出来 | [风格测试](references/风格测试.md) |

前六项合成一份文件，用 [导演阐述与视觉圣经模板](templates/导演阐述与视觉圣经模板.md)，存进资料库并在项目索引登记。画面预设同时写入“影像与声音参数”槽位。

各流程档位做到什么程度：

| 档位 | 要求 |
|---|---|
| 小样 | 一页基调说明：立意、基调、三条视听策略、主色与光线倾向。风格测试一张即可 |
| 标准 | 全部七项，风格测试一轮 |
| 精品 | 全部七项，风格测试多轮对比，表演基调细化到每个主要人物 |

## 五条原则

1. **每个选择都答得出为什么。** 为什么是冷色，为什么用长焦，为什么这里没有音乐。答案要落到观众承诺、主题或人物上。答不出来的选择只是装饰。
2. **具体到下游可以照做。** “电影感”“高级”“有质感”无法执行。写成光比的大小、主色的色相、焦段的倾向、线条的粗细，资产和分镜才能照着做，评审才能照着查。
3. **少而一致。** 三到五条贯穿全片的规则，比二十条各管一处的规则有用。风格来自重复。
4. **规则是为了被打破一次。** 全片守着一条规则，只在最重要的时刻打破它，那个时刻就有了分量。在阐述里写明哪条规则在哪里破例。
5. **做得出来才算数。** 所选模型做不出来的风格，写得再漂亮也没有用。风格测试就是为了验证这一点，没通过就回来改阐述，或请用户换模型。

## 和档案的关系

- 形态档案决定用哪一套语言：真人短剧和 3DCG 用摄影的语言（焦段、景深、布光），2D 动画和漫剧用画面设计的语言（线条、上色、构图、分层）。
- 题材档案提供起点：这类片子的观众习惯什么样的视听。可以偏离，但要知道自己在偏离，并写明理由。
- 用户给的参考和明确的喜好，优先于档案。

## 用户确认

基调是审美判断，最终由用户决定。为了不拖慢流程，只请用户看一次：

- 写完导演阐述和视觉圣经，直接做风格测试，然后把立意、基调和风格测试的画面放在一起请用户确认（风格确认点）。用户看到画面再判断基调，比只看文字准确得多。
- 用户不认可时，按风格测试一节的诊断表判断是改阐述还是改测试，只改需要改的部分。
- 认可的范围要写清楚。认可画风不等于认可了人物的脸或场景。

用户事先表示希望先看文字方向的，再拆成两次。

## 评审与交接

- 按 [评分表与反模式](references/评分表与反模式.md) 评分并附证据，档位要求时做独立评审。
- 交给资产模块：视觉圣经、画面预设表、风格测试结果及其认可范围。
- 交给分镜模块：情绪曲线、镜头或画面规则、画面预设表、表演基调。
- 交给剪辑模块：情绪曲线、声音概念、色彩脚本（供调色）。
- 交给物料模块：主色、质感、视觉母题。

下游发现阐述执行不了或互相矛盾时，回到这里修改并出新版本，不在下游各自变通。
