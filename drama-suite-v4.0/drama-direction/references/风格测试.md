# 风格测试

风格测试用很少的几张图，验证导演阐述和视觉圣经在所选模型上做得出来。它是整条流程里最早见到画面的时刻，也是改方向最便宜的时刻。

## 测什么

只测风格：色彩、影调、光线、质感、线条或渲染方式、整体的感觉。

不测、也不代表通过的东西：人物的脸和身份、服装细节、场景布局、道具。这些由资产模块各自设计和验收。风格帧里出现的人物和场景只是载体。

## 选哪几帧

选最能代表全片、也最容易暴露问题的画面，两到三张：

1. **一张人物近景。** 检查肤色、光比、质感或线条。
2. **一张带人物的主要场景。** 检查色彩关系、空间里的光、人物与背景的风格是否统一。
3. **一张最难的画面。** 例如夜戏、强反差、情绪最高点的色彩，或视觉母题第一次出现的样子。

小样档一张即可，选第 2 种。精品档每种可以做多个方案对比。

不要在这一步展开全片分镜，也不要锁定镜头时长或生成包。

## 做法

1. **写每一帧的画面说明。** 根据视觉圣经和对应场景的画面预设：画面内容、色彩、光线、质感、构图。每一项都能对回圣经里的某条规定。
2. **按生图模型的适配卡转成请求。** 适配卡不存在或未核验时，先补卡。
3. **生成。** 生成要花钱时先确认授权范围。自动模式直接提交；手动模式输出请求包，请用户在平台上生成后放回指定目录。做法见 [模型适配规范](../../drama-control/references/模型适配规范.md)。
4. **对照检查。** 实际看图，逐条对照视觉圣经：

| 检查项 | 圣经的规定 | 图上的实际情况 | 是否达到 |
|---|---|---|---|
| 主导色与强调色 | | | |
| 影调与反差 | | | |
| 光的方向和质地 | | | |
| 质感，或线条与上色 | | | |
| 肤色 | | | |
| 与基调关键词的吻合 | | | |

没看到图就不填这张表。

5. **请用户确认。** 把风格帧和这张对照表一起给用户，说明哪些达到了、哪些没有。风格是否成立由用户判断。

## 没达到怎么办

先判断原因，再决定动作：

| 原因 | 动作 |
|---|---|
| 画面说明没写清，或转成请求时丢了约束 | 改说明，重新生成 |
| 这个模型做不出这种风格 | 把发现记入适配卡的已知弱点；与用户商量调整阐述，或更换模型 |
| 做出来了，但用户看了觉得不是想要的 | 回到导演阐述改基调，这是阐述的问题，不是测试的问题 |
| 圣经里的两条规定互相冲突 | 回到视觉圣经取舍 |

同一个方向试了两轮仍然达不到，停下来和用户商量，不继续消耗。

## 记录

每次测试记下：

- 测试编号、日期、所用模型和适配卡版本
- 每一帧的画面说明、实际发送的请求、输出文件的位置
- 对照表
- 用户的结论和**认可范围**，写成明确的句子，例如：“认可色彩、光线和整体质感。人物的脸、服装和场景布局不在认可范围内。”
- 没通过的版本也保留，标明被否定的原因。被否定的图不进入后续的参考。

用户认可的风格帧登记为“风格对标”资产，交给资产模块。它只控制风格，不控制身份、服装和场景。

## 模型更换之后

更换生图或生视频模型，风格测试要重做，因为同样的描述在不同模型上的结果不同。
