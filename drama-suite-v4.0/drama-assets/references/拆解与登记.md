# 拆解与登记

## 五类资产总表

用 [五类资产总表模板](../templates/五类资产总表模板.md)。总表回答两个问题：这一集需要什么，每一样现在是什么状态。

| 类别 | 包含 |
|---|---|
| 角色 | 身份（脸）、全身与服装、表情与关键动作、年龄或造型变体、比例 |
| 场景 | 布局、出入口与动线、可操作区域、前中后景、实景光源、不同拍摄方向 |
| 道具 | 外观、实物尺寸、持握方式、正反方向、状态变化 |
| 风格对标 | 风格测试中用户认可的风格帧，及其认可范围 |
| 声音 | 角色声线、旁白、标志性声音、需要预先确定的环境声 |

**拆解步骤：**

1. 逐段读拆解表，每一段都问：谁在场、在哪里、碰了什么、发出什么声音、外观有没有变化。
2. 每个需求落到总表的一行，记下它出现的源段落编号。
3. 再反过来检查一遍：总表末尾的“源段落覆盖”表，每一段都能找到对应的资产，或者写明不需要的原因。
4. 按重要程度排序：主要角色、反复出现或有交互的道具、关键场景优先；路人和一闪而过的背景物按需处理，可以标“不适用”并写原因，不虚增工作。

拆解阶段可以预判某场戏大概要什么景别、什么动作，用来判断资产需求，例如判断是否需要背面图、是否需要手部特写用的道具图。这只是需求分析，不是分镜。

## 控制权

每张参考图、每段参考声音，都要写清它控制哪些属性：

| 属性 | 通常的权威参考 |
|---|---|
| 脸与身份 | 身份图 |
| 体型、身高、头身比 | 全身图或比例图 |
| 服装、发型、配饰 | 服装图，按造型分别登记 |
| 空间布局 | 场景布局图 |
| 道具外观与尺寸 | 道具图 |
| 画风、色彩、质感 | 风格对标 |
| 声音 | 声线样本 |

**规则：**

- 同一个属性只有一个当前权威。两张图都在管同一样东西时，必须指定一张，另一张降为非权威或停用。
- 场景图、风格图、氛围图里出现的人，不能覆盖角色身份。
- 身份图上人物穿的衣服和本场造型不一致时，不能指望靠文字让模型换衣服。优先用同时呈现原脸和本场服装的参考；没有就补做一张。
- 多年龄段或多造型的人物，所有变体共享同一个身份基准，各自登记适用的场次。
- 已确认的脸不能用文字描述重新生成一张近似的来替代。修复要以原参考为基础。

## 登记

每一项写入资产索引（给人看）和资产登记（给脚本核对），字段：

编号、类别、名称、相对路径、SHA256、版本、前一版、控制的属性、适用场次、实际像素或时长、来源、状态、验收证据、确认来源与日期。

**版本规则：**

- 修改出新版本，不覆盖旧文件。
- 状态用共用规则规定的词。被否定的版本标“停用”，写原因。
- 图片记实际像素。请求里写了某个分辨率不代表输出就是这个分辨率。
- 中断没有输出的生成记为中断，不记为已生成。

**平台托管的资产**（上传到平台、用平台编号引用的）另记：对应的本地文件、平台上的位置和编号、用途、状态。平台上同名或显示有效不等于就是这一份，要核对到具体文件。

## 逐包核对

每个生成包提交前，资产这一侧要核对四件事。分镜和生成模块会调用这张清单。

1. **清单。** 这个包需要哪些资产，每一项控制什么。
2. **文件。** 每一项的实际文件存在、是当前版本、在白名单里。
3. **内容。** 打开看过：图上的人、衣服、道具和本包的需求一致。不只看文件名。
4. **附带。** 实际发送的请求里确实带上了它，用途写对了。“同上”“见文件夹”不算。

每项的状态：已核对可提交、待用户确认、缺失。缺失的不提交，先补。

模型的参考图数量不够用时，先调整分包或制作合适的组合参考，不能为了凑数量省掉必要的控制属性。

## 冻结与白名单

资产关卡文件级通过后，总控冻结本集用到的资产版本，生成白名单。之后：

- 生成只能用白名单里的文件。缺东西先补进白名单，不从候选图、废稿、旧截图、聊天附件里临时借。
- 已冻结的资产要修改，出新版本，由总控把用到它的分镜和生成包标为需复核。
