# 资产

资产是 AI 剧集里一致性的唯一来源。人物在第 3 镜和第 30 镜是不是同一个人，场景的门是不是还在左边，杯子是不是还是那只杯子，都取决于这里给出的参考是否清楚、唯一、经过验收。

这个模块做两件事：**设计**，让资产本身好看、有辨识度、服务故事；**管理**，让每一项都可追溯、控制权明确、实际验收过。旧版只做了后一件。

## 开工

1. 读 [共用规则](../drama-control/references/共用规则.md)。
2. 从项目索引读：形态档案（资产规格和一致性重点在这里），导演阐述与视觉圣经，画面预设表，风格测试的认可范围，人物小传与关系，本集的逐段拆解表，资产索引，尺寸与连续性，项目资料库里的 `patterns/assets.md`（有的话）。
3. 确认生图模型和配音模型的适配卡已填好。

## 工作顺序

1. **拆解。** 把逐段拆解表汇总成 [五类资产总表](templates/五类资产总表模板.md)：角色、场景、道具、风格对标、声音。每一项对应到它出现的源段落。做法见 [拆解与登记](references/拆解与登记.md)。
2. **查库存。** 逐项看已有的文件，决定沿用、修复还是新做。先看实物再决定，不凭文件名判断。
3. **设计。** 新做的项先写设定卡，说清楚它为什么长这样，再生成。
   - 角色：[角色设计](references/角色设计.md)
   - 场景和道具：[场景与道具设计](references/场景与道具设计.md)
   - 声线：[声线设计](references/声线设计.md)
4. **制作。** 按形态档案的资产规格和适配卡生成或修复。要花钱时先确认授权，没有接口时输出请求包，见 [模型适配规范](../drama-control/references/模型适配规范.md)。
5. **验收。** 实际看图、听声音，按 [资产验收](references/资产验收.md) 逐项检查并登记。
6. **交关卡，分两次。** 总表和设定卡齐了，交总控过资产关卡设计级，分镜就可以开始；资产实际做完、验收过，再交文件级。设计级通过后，资产制作和分镜同时进行。

全剧级做一次主要角色、常用场景和固定声线；单集级只补本集新增的项，并核对已有资产在本集的状态（换装、受伤、道具损坏）。

## 四条原则

1. **设计先于生成。** 先回答“这个人物为什么穿这件衣服”“这个房间的光从哪里来”，再写生成请求。没有设计的资产，靠模型的默认审美，结果千篇一律。
2. **辨识度优先于精致度。** 短剧在手机上看，人物常常很小、一闪而过。剪影、主色、发型一眼能分清，比面部细节画得多精细更重要。
3. **一个属性只有一个权威参考。** 脸由身份图管，衣服由服装图管，布局由场景图管，画风由风格对标管。一张图可以管多样，但要写清楚管哪几样；两张图不能同时管同一样。
4. **看过听过才算有。** 文件存在不等于验收，生成成功不等于可用。没有实际看过听过的，标“未核验”。

## 和其他模块的边界

- 风格由导演模块定，资产照视觉圣经执行。资产阶段发现风格做不出来或互相矛盾，退回导演模块，不自行改风格。
- 资产阶段可以做光影标定测试，验证资产在本片光线下的样子，但不展开正式分镜、不锁定镜头时长和生成包。
- 剧本要求的东西做不出来时，回剧本模块讨论改写，不靠分镜或生成去碰运气。

## 交付前

1. 按 [评分表与反模式](references/评分表与反模式.md) 评分并附证据，档位要求时做独立评审。
2. 总表每一行都有状态和实际验收的证据，不适用项写了原因。
3. 资产索引和资产登记已更新，旧版本保留。
