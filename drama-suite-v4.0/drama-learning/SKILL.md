# 参考学习与复盘

学习的目的是让下一次做得更好。它有两个来源：外部的参考（别人的作品做对了什么），和自己的复盘（这一集什么做对了、什么做错了）。

学到的东西要变成具体的、可执行的规律，放到会被读取的地方。“这个片子很有质感”不是学习成果；“夜戏用单侧窗光，人物脸部的暗面保留可读的细节，背景压到几乎全黑，适用于悬疑题材的对峙戏”才是。

## 开工

1. 读 [共用规则](../drama-control/references/共用规则.md)。
2. 从项目索引读和参考相关的槽位，以及项目资料库里已有的 `patterns/` 和参考卡。
3. 确认任务：

| 任务 | 做法 |
|---|---|
| 学习一个或几个参考 | [参考拆解方法](references/参考拆解方法.md)，写参考卡 |
| 全量学习一个或多个账号 | [账号视频学习](references/账号视频学习.md) |
| 学习已有的剪辑工程 | 剪辑模块的 [草稿学习](../drama-editing/references/草稿学习.md) |
| 每集结束后复盘 | [沉淀与复盘](references/沉淀与复盘.md)，写复盘记录 |
| 把学到的写进规律或档案 | [沉淀与复盘](references/沉淀与复盘.md) |

## 四条原则

1. **看实物。** 实际看视频、听声音、读剧本。只看了抽帧，不能说分析了运镜、节奏或声音。不能访问的部分写明未读取。
2. **分清事实和推断。** 看到的是事实（“这一镜人物在画面左侧，背景是暗的”），猜的是推断（“大概用了长焦”）。单帧推测的焦段、光圈不能写成实测值。
3. **提炼机制，不复制内容。** 学的是“产生什么效果，靠什么实现，什么时候有效”，不是别人的角色、台词、构图、曲目。
4. **沉淀要授权。** “学习一下”只保存分析和候选建议。用户说“入库”“锁定”“以后这样做”，才写进规律文件。不自行覆盖已经确认的规则。

## 沉淀到哪里

| 层级 | 位置 | 需要的授权 |
|---|---|---|
| 本项目的规律 | 项目资料库的 `patterns/` | 用户说入库、锁定、以后这样做 |
| 题材或形态档案 | 项目的 `profiles/`，或套组的 `profiles/` | 用户明确同意推广到这一类题材或形态 |
| 通用内核 | 套组各模块的 references | 用户明确要求修改 skill |

一个项目里的人物、故事、具体的视觉数值，只留在这个项目里，不推广到档案和内核。

## 交给其他模块

学到的规律按内容交给对应的模块，见 [沉淀与复盘](references/沉淀与复盘.md) 的分配表。风格方面的参考交给导演模块，由它决定是否纳入视觉圣经；参考的角色脸不覆盖项目的身份资产。
