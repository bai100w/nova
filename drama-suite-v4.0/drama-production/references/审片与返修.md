# 审片与返修

## 怎么看

- 逐个子镜完整看，至少看两遍：第一遍看整体，第二遍逐项对照检查清单。
- 逐句听台词，对照确认台词表。
- 看动作和口型需要连续播放。只看抽帧或缩略图时，这两项标“未核验”。
- 把相邻的子镜连起来看一遍，检查接得上不上。
- 没有能力看视频或听音频时，如实说明，请用户审，或标“未核验”。

## 检查清单

**每个子镜都查：**

| 项 | 看什么 |
|---|---|
| 台词 | 完整、逐字、顺序正确；说话人对；没有多出来的话 |
| 身份 | 脸是同一个人；年龄阶段对 |
| 服装与外观 | 与本场造型一致 |
| 比例 | 人与人、人与道具、人与空间的比例对 |
| 站位与姿势 | 与起始画面和连续性状态表一致 |
| 动作 | 执行者对，有起点和结果，没有不自然的回弹和重复 |
| 表演 | 有触发、有反应，情绪可读，幅度符合表演基调 |
| 手与道具 | 手指正常，持物的手对，道具的状态对 |
| 镜头 | 景别、角度、运动接近设计；焦点在该在的地方 |
| 光线 | 方向与场景光源一致；脸可读；没有不合理的光 |
| 画风 | 与视觉圣经和风格对标一致 |
| 口型与声线 | 口型对得上（形态要求时）；声线是指定的那一个 |
| 声音 | 符合项目对音乐、音效、环境声的规定；没有截断和杂音 |
| 负面约束 | 没有字幕、水印、多余人物等项目禁止的内容 |
| 开头与结尾 | 开头有没有没站稳的部分；结尾有没有闪烁、重置；实际的结束状态是什么 |

**按形态的重点**，见形态档案第 8 节“高发缺陷与审片重点”。

## 五级分类

| 结论 | 含义 | 下一步 |
|---|---|---|
| 通过 | 可以直接剪 | 记录可用的时间段和实际结束状态 |
| 可用部分 | 有一段可用，足够剪辑需要 | 记录可用带和不可用的原因，交剪辑 |
| 可后期修复 | 问题小，后期能处理：轻微色偏、边缘瑕疵、可以裁掉的部分 | 写清问题和建议的处理，交剪辑 |
| 需重生成 | 问题在生成环节能解决 | 诊断，定向返修 |
| 需改上游 | 问题在分镜、资产或剧本 | 退回对应模块，说明原因 |

“通过”要求实际看过听过。只看过一部分的，写明看过的范围。

## 诊断

每个问题先判断原因出在哪一层，再决定怎么改。

| 现象 | 常见原因 | 可以试的改法 |
|---|---|---|
| 人物不像同一个人 | 身份参考没附带或被其他图干扰；镜头太远或角度太偏 | 检查参考的附带和控制权；改用更近或更正的角度；用已通过的帧作为首帧 |
| 服装不对 | 身份图上的服装与本场冲突 | 换用同时呈现原脸和本场服装的参考 |
| 多出人物或道具 | 参考图里有其他人或物；子镜范围没限定 | 换参考；在请求里限定出镜范围 |
| 比例不对 | 没附带比例参考；动作涉及靠近或同框 | 附带比例参考；拆成单人镜头 |
| 动作不对或变形 | 一镜里动作太多；动作本身是模型弱项 | 一镜一个动作；按可制作性审查的替代写法改分镜 |
| 表演平或过度 | 请求里只有形容词；幅度没写 | 改成具体的动作和幅度 |
| 光线跳 | 请求里光源方向写错，或反打时直接复制 | 按场景光源和机位重新换算 |
| 口型不对 | 一个镜头里多人说话；台词太长 | 拆成单人说话的镜头；拆短 |
| 运动不对 | 运动太复杂或太长 | 简化为固定或单一运动，靠剪辑实现变化 |
| 画风偏 | 风格参考没附带；请求的风格描述和视觉圣经不一致 | 附带风格对标；按适配卡调整写法 |
| 开头或结尾有缺陷 | 模型的常见现象 | 请求时长留余量，剪辑时裁掉 |

**判断是否该退回上游：**

- 同一类问题在多个镜头反复出现 → 很可能是分镜的写法或资产的问题。
- 改了两轮请求都没解决 → 很可能是模型的能力边界，需要改分镜绕开。
- 结果和设计一致，但看起来不好 → 是设计的问题，退回分镜或导演模块。

## 返修

- 每次只改诊断出的原因。多个相关的错误可以一起改，但要记录。
- 写清这次改了什么、为什么，记进请求登记。
- 不把同一个请求原样再提交，除非诊断结论是“模型的随机波动”，并且这次是有限的几次尝试之一。
- 保留每一个版本的输出。
- 同一个问题两轮没解决，停下来报告用户。

## 续接

用上一个片段的结尾作为下一个片段的开头时：

- 只用已经通过审片的片段。待审的、被否定的、有连续性错误的片段不能用来续接。
- 用实际观察到的结束帧，不是计划的结束状态。
- 续接帧要干净：人物站稳、没有动作中的模糊、没有缺陷。

## 回写

审片结束后：

- 每个子镜的结论写进审片记录和制作状态。
- 实际的结束状态写回连续性状态表。和计划不同的，检查后续的包是否要调整。
- 稳定出现的模型问题写进适配卡的“已知弱点”，附上规避的办法。
- 发现的规律（某种写法效果特别好或特别差）交给学习模块，作为候选规律。
