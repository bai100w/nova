# 生成与审片

这个模块是设计变成画面的地方，也是花钱的地方。它的任务是：把分镜的设计完整地交给模型，把模型的结果如实地看清楚，出了问题找到原因再改。

不变的立场：生成成功不等于通过，写进请求不等于模型做到了，同一个请求再提交一次不叫返修。

## 开工

1. 读 [共用规则](../drama-control/references/共用规则.md)。
2. 确认前置条件，缺一项就停在这一步，说明缺什么：
   - 资产关卡文件级和预演关卡已通过
   - 本集的制作包已登记，白名单可用
   - 分镜和生成包已锁定
   - 所用模型的适配卡已核验且在有效期内
   - 付费生成的授权、预算上限、每镜重试上限已明确
3. 读制作包：生成包、分镜画面卡、连续性状态表、资产白名单、项目的负面约束、适配卡。
4. 确认运行环境里真实可用的工具，决定走自动模式还是手动模式。

## 工作顺序

1. **组装请求。** 按适配卡的写法，把生成包翻译成该模型的请求，附上白名单里的参考。见 [请求组装与提交](references/请求组装与提交.md)。
2. **提交前检查。** 逐项过阻断条件。有问题只阻断受影响的包，其他包继续。
3. **提交。** 自动模式直接提交并登记任务编号；手动模式输出请求包，等用户放回结果。
4. **审片。** 实际看每一个子镜、听每一句台词，按 [审片与返修](references/审片与返修.md) 分级。
5. **返修。** 先诊断，再定向修改，不碰运气。问题在上游的退回上游。
6. **回写。** 审片结论写进制作状态；实际的结束状态写回连续性状态表；稳定出现的问题写进适配卡的已知弱点。

## 四条原则

1. **请求完整，不做二次概括。** 分镜写了什么，请求里就要有什么：起始画面、表演、镜头、光线、完整台词、声音、结束状态、负面约束。模型不支持的参数改写成可见效果，不能删掉。
2. **只用白名单。** 参考只来自制作包。缺东西先补包，不临时借用候选图、旧版本或聊天里的图片。
3. **审片看实物。** 逐镜看，逐句听。没看到没听到的标“未核验”。只看了缩略图或抽帧，不能说检查了动作和口型。
4. **先诊断，后返修。** 每次重试都要能说出这次改了什么、为什么。同一个问题两轮还没解决，停下来报告用户，说明可选的方案。

## 和其他模块的边界

- 分镜不完整、自相矛盾、超出模型能力，退回分镜模块，不在请求里自己补设计。
- 资产缺失或冲突，退回资产模块。
- 台词装不下，退回剧本和分镜，不删台词、不要求加快语速。
- 问题可以在后期修（轻微的色偏、可以裁掉的边缘瑕疵），标“可后期修复”交给剪辑，不必重新生成。
